# 中文技术文档写作

底本：阮一峰《中文技术文档的写作规范》（公共领域）。写作时按本页流程执行；需要查条款读 [references/style-guide.md](references/style-guide.md)，需要对照改法读 [references/examples.md](references/examples.md)，交付前按 [references/checklist.md](references/checklist.md) 自检。

## 先确认四件事

1. **文档类型**：README、API 参考、设计文档、教程、发布说明。类型决定骨架，不改变写作规则。
2. **目标读者**：读者需要先懂什么，决定解释顺序和术语密度。
3. **发布渠道**：仓库 Markdown、官网、PDF、帮助中心。渠道影响标题层级、链接和图片写法。
4. **必须保留的写法**：产品名、术语表、品牌大小写、既有 API 名称。不要擅自“纠正”它们。

缺少以上信息且会影响产出时，问一次；不影响就先按保守默认写，并在交付时说明假设。

## 工作流

1. **取证**：先读现有文档、代码、接口定义或用户给的原文。不凭记忆补事实；无法确认的内容标注“待确认”，不编造。
2. **定骨架**：先写标题大纲，最多四级。检查不跳级、无孤立编号、子标题不与父标题同名，再动笔写句子。
3. **起草**：一个段落一个主题，中心句放段首；先结论后细节；一段不超过七行，最佳不超过四行。
4. **改写**：长句拆到 20 字上下；被动改主动，否定改肯定；删形容词、空动词和套话；统一术语。
5. **机器自检**：运行 `scripts/check-style.ps1`，扫中英文空格、全角半角、重复标点、标题层级等机械问题。Windows 下用 `powershell -NoProfile -ExecutionPolicy Bypass -File` 调用。
6. **人工自检**：按 `references/checklist.md` 逐项过；最后通读一遍，只改错，不再加内容。

## 按文档类型调整骨架

- **README**：一句话定位 → 安装 → 最小可用示例 → 常用用法 → 配置 → 相关链接。示例必须能直接运行。
- **API 参考**：按资源或函数分组；每项写用途、签名、参数（类型、必填、默认值）、返回值、错误、示例。同一字段在各处用同一名称。
- **设计文档**：背景与问题 → 目标与非目标 → 方案 → 取舍与替代方案 → 影响面（兼容性、性能、安全）→ 迁移与回滚。结论前置。
- **教程**：先给完成后的效果，再分步骤；每步一个动作、一个可验证结果；命令与输出分开写。
- **发布说明**：按“新增、变更、修复、废弃、安全”分组；写用户可感知的变化，不堆提交记录。

## 交付标准

- 术语、产品名、大小写全文一致；英文缩写首次出现给出中文全称。
- 代码、命令、路径、字段名用行内代码标记，且与实际一致。
- 标题层级连续，段落不超七行，长句已拆。
- 机械检查零告警，或每条告警都有明确理由。
- 交付时说明：改了哪些类型的问题、保留了哪些原文写法及原因、哪些内容待确认。
