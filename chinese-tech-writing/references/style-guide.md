# 中文技术文档写作规范（详版）

> 底本：阮一峰《中文技术文档的写作规范》（公共领域）。条款保留原意，示例按技术文档场景改写；标注「补充」的内容是本 skill 增加的实践，不是原规范条款。
>
> 记号：**必须**表示硬规则，违反即视为缺陷；**建议**表示默认遵守，有明确理由可以例外。

## 0. 总则

1. **准确优先**。术语、参数、命令、返回值必须与实现一致；宁可少写，不写没把握的内容。
2. **一致性优先于偏好**。同一概念只用一种写法；数字与汉字的间距、日期格式、列表标点全文统一。
3. **最小改动**。审校时只改有规范依据或明确错误的地方，不借机重写作者的语气和结构。
4. **读者任务优先**。先回答“读者要做什么”，再决定章节顺序；背景知识放在需要它的位置，不堆在开头。
5. **冲突裁决**。产品名与品牌大小写 > 项目术语表 > 本规范 > 个人语感。冲突时在交付说明里写一句理由。

## 1. 标题

### 1.1 层级

标题最多四级：

```markdown
# 一级标题（文档标题）

## 二级标题（主要部分）

### 三级标题（某一方面）

#### 四级标题（某一子项）
```

### 1.2 原则

（1）**不得跳级**。一级标题下不能直接出现三级标题；补上二级标题，或把内容并入一级章节。

```markdown
# 一级标题

### 三级标题
```

（2）**避免孤立编号**。同级标题只有一个时，删掉这一级编号，内容并到上一级。只有一个三级标题的章节不成立。

```markdown
## 二级标题 A

### 三级标题 A

## 二级标题 B
```

（3）**下级标题不重复上级标题的名字**。二级标题“概述”下再写三级标题“概述”属于重复；改写成具体方面，例如“适用范围”。

（4）**慎用四级标题**。四级标题容易造成又长又碎的章节；三级标题下有并列内容时，优先用项目列表，必要时用加粗编号。

```markdown
### 部署

**（1）准备环境**

**（2）上传安装包**

**（3）启动服务**
```

### 1.3 补充：标题措辞

- 用名词短语或动宾短语，同级标题结构平行。
- 标题末尾不加句号、逗号、分号、冒号；问号和感叹号只在确有语气时使用。
- 标题只指路，不解释；一句话说不清的内容放到正文第一段。
- 标题里的英文保留原样，不强行翻译 API 名、产品名。

## 2. 文本

### 2.1 字间距

（1）中文字符与英文字母之间，**必须**有一个半角空格。

```
错误：本文介绍如何快速启动Windows系统。
正确：本文介绍如何快速启动 Windows 系统。
```

（2）中文字符与阿拉伯数字之间可以加半角空格，也可以不加，但全文必须统一。

```
统一写法 A：2011年5月15日，我订购了5台笔记本电脑与10台平板电脑。
统一写法 B：2011 年 5 月 15 日，我订购了 5 台笔记本电脑与 10 台平板电脑。
```

半角百分号视同数字处理，百分号紧贴数字，与汉字的间距按数字规则统一。

（3）英文单位不翻译时，数字与单位符号之间留一个半角空格。

```
一部容量为 16 GB 的智能手机
1 h = 60 min = 3,600 s
```

（4）半角英文字母、数字与全角标点之间**不留空格**。

```
错误：他的电脑是 MacBook Air 。
正确：他的电脑是 MacBook Air。
```

### 2.2 句子

句子长度按下面的阈值判断（不含标点）：

| 长度 | 处理 |
| --- | --- |
| 20 字以内 | 理想 |
| 20～29 字 | 可以接受 |
| 30～39 字 | 语义必须明确才接受，否则拆句 |
| 40 字以上 | 不可接受，必须拆 |

（1）避免长句。以逗号分隔的长句，总长度不超过 100 字或正文的 3 行。

```
错误：本产品适用于从由一台服务器进行动作控制的单一节点结构到由多台服务器进行动作控制的并行处理程序结构等多种体系结构。
正确：本产品适用于多种体系结构。无论是由一台服务器（单一节点结构），还是由多台服务器（并行处理结构）进行动作控制，均可以使用本产品。
```

（2）用简单句和并列句，避免多层复合句。

```
并列句：他昨天生病了，没有参加会议。
复合句：那个昨天生病的人没有参加会议。
```

（3）用肯定句表达同样的意思。

```
错误：请确认没有接通装置的电源。
正确：请确认装置的电源已关闭。
```

（4）避免双重否定。

```
错误：没有删除权限的用户，不能删除此文件。
正确：用户必须拥有删除权限，才能删除此文件。
```

### 2.3 写作风格

（1）用主动语态。

```
错误：假如此软件尚未被安装，
正确：假如尚未安装这个软件，
```

（2）用正式书面语，不用口语、网络用语和夸张修辞。

```
错误：这个功能简直无敌，谁用谁知道！
正确：这个功能可以把配置时间缩短约 30%。
```

（3）用现代汉语常用词，不用冷僻词、生造词、文言词。

```
错误：这是唯二的快速启动的方法。
正确：这是仅有的两种快速启动的方法。
```

（4）区分“的、地、得”。

```
她露出了开心的笑容。（形容词 + 的 + 名词）
她开心地笑了。（副词 + 地 + 动词）
她笑得很开心。（动词 + 得 + 补语）
```

（5）代词必须有唯一、明确的指代对象。

```
错误：从管理系统可以监视中继系统和受其直接控制的分配系统。
正确：从管理系统可以监视两个系统：中继系统，以及受中继系统直接控制的分配系统。
```

（6）名词前不要堆形容词和长定语。

```
错误：此设备的使用必须在接受过本公司举办的正式的设备培训的技师的指导下进行。
正确：此设备必须在技师的指导下使用，且指导技师必须接受过本公司举办的正式设备培训。
```

### 2.4 英文处理

（1）英文原文的复数译成中文时还原为单数。

```
英文：...information stored in random access memory (RAMs)...
中文：⋯⋯存储在随机存取存储器（RAM）里的信息⋯⋯
```

（2）外文缩写可以用半角圆点。

```
U.S.A.
Apple, Inc.
```

（3）中文语境里不用英文省略号 `...`，改用中文省略号 `⋯⋯`。

```
英文：5 minutes later...
中文：5 分钟过去了⋯⋯
```

（4）英文书名、电影名改用中文表达时，双引号改为书名号。

```
英文：He published an article entitled "The Future of the Aviation".
中文：他发表了一篇名为《航空业的未来》的文章。
```

（5）英文词汇第一次出现时，在括号里给出中文，之后直接用缩写。

```
IOC（International Olympic Committee，国际奥林匹克委员会）。这样定义之后，后文可以直接写“IOC”。
```

（6）专有名词每个词首字母大写；普通名词短语不大写。

```
American Association of Physicists in Medicine（美国医学物理学家协会）
online transaction processing（在线事务处理）
```

### 2.5 补充：技术文档常用句式

- 操作步骤用祈使句：“打开配置文件”，不写“用户应该打开配置文件”。
- 条件和结果前置：“如果端口被占用，修改 config.yaml 中的 port。”
- 去掉“进行、加以、予以”这类空动词：“对配置进行检查”改为“检查配置”。
- 一段里不叠两层以上定语；超过就拆成两句。
- 代码标识符原样保留，不翻译，不在标识符内部加空格。

## 3. 段落

### 3.1 原则

- 一个段落只讲一个主题，或只有一个中心句。
- 中心句放段首，后面的句子为中心句服务。
- 段落不超过七行，最佳长度不超过四行。
- 用陈述、肯定的语气，不用感叹语气。
- 段落之间空一行。
- 段首不留空白字符。

### 3.2 引用与转载

- 引用第三方内容时注明出处。

```
One man's constant is another man's variable. — Alan Perlis
```

- 全文转载时，在开头显著位置注明作者、出处，并链接原文。

```
本文转载自 WikiQuote
```

- 使用外部图片时，在图片下方或文末标明来源。

```
本文部分图片来自 Wikipedia
```

### 3.3 补充：列表

- 列表项与引导句语法一致：都以名词开头，或都以动词开头。
- 列表项的句末标点统一：要么都用分号，要么都不用；最后一项用句号。
- 列表项超过七条时，考虑分组或改成表格。
- 列表嵌套不超过两层；再深说明结构需要重排。

## 4. 数值

### 4.1 半角数字

阿拉伯数字一律使用半角形式。

```
错误：这件商品的价格是１０００元。
正确：这件商品的价格是 1000 元。
```

### 4.2 千分号

千位以上加千分号（半角逗号）。四位数可加可不加，四位以上必须加。

```
XXX 公司的实收资本为 ￥1,258,000 人民币。
1000 与 1,000 都可以；12,500 必须加。
```

### 4.3 货币

货币用阿拉伯数字：符号写在数字前，或中文名称写在数字后。

```
$1,000
1,000 美元
```

英文货币名称参考 ISO 4217。

### 4.4 数值范围

用波浪线 `～` 或一字线 `—` 连接，前后两个值都带上单位或百分号。

```
132 kg～234 kg
67%～89%
```

### 4.5 变化程度

“了”表示增量，“到”表示定量，不能混用。

| 表述 | 含义 |
| --- | --- |
| 增加到过去的两倍 | 过去是 1，现在是 2 |
| 增加了两倍 | 过去是 1，现在是 3 |
| 降低到 80% | 原来是 100，现在是 80 |
| 降低了 80% | 原来是 100，现在是 20 |

不能用“降低 N 倍”“减少 N 倍”：减少一倍意味着数值归零。要写“降低百分之几”或“减少百分之几”。

### 4.6 补充：单位与时间

- 数字与单位符号之间留空格：`16 GB`、`60 s`、`25 °C`、`-20 °C 至 -10 °C`。
- 百分号紧贴数字：`6.5%`，不写 `6.5 %`。
- 时间用半角冒号：`8:00`。
- 日期全文统一：`2011 年 5 月 15 日` 或 `2011-05-15`，不要混用。

## 5. 标点符号

### 5.1 原则

（1）中文语句的标点一律用全角，与全角文字视觉一致。
（2）整句是英文时，该句用英文半角标点。
（3）句号、问号、叹号、逗号、顿号、分号、冒号不得出现在行首。
（4）点号（句号、逗号、顿号、分号、冒号）不出现在标题末尾；标号（引号、括号、破折号、省略号、书名号等）可以。

### 5.2 句号

（1）中文句子结尾用全角句号 `。`

（2）句末有括号注释时，句号在括号之外。

```
错误：关于文件的输出，请参照第 1.3 节（见第 26 页。）
正确：关于文件的输出，请参照第 1.3 节（见第 26 页）。
```

### 5.3 逗号

（1）逗号 `，` 表示句子内部的一般性停顿。

（2）避免“一逗到底”：一个段落里不要所有停顿都用逗号，该用顿号、分号、句号的地方要用对。

### 5.4 顿号

（1）句内并列词用顿号 `、`，即使并列项是英文词。

```
错误：我最欣赏的科技公司有 Google, Facebook, 腾讯, 阿里和百度等。
正确：我最欣赏的科技公司有 Google、Facebook、腾讯、阿里和百度等。
```

（2）英文句子内部并列用半角逗号。

```
Microsoft Office includes Word, Excel, PowerPoint, Outlook and other components.
```

（3）中文并列项的最后一项用“和”连接，读起来更连贯。

```
较好：我最欣赏的科技公司有 Google、Facebook、腾讯、阿里和百度等。
```

### 5.5 分号

分号 `；` 表示复句内部并列分句之间的停顿。分句内部已经用逗号时，分句之间用分号。

### 5.6 引号

（1）引用时用全角双引号 `“ ”`，前后两个符号不同。

```
许多人都认为客户服务的核心是“友好”和“专业”。
```

（2）引号内再用引号时，外层用双引号，内层用单引号 `‘ ’`。

```
鲍勃解释道：“我要放音乐，可萨利说，‘不行！’。”
```

### 5.7 括号

（1）补充说明用全角圆括号 `（）`，括号前后不加空格。

```
请确认所有的连接（电缆和接插件）均安装牢固。
```

（2）四种括号的名称：

| 符号 | 英文 | 中文 |
| --- | --- | --- |
| `{ }` | braces 或 curly brackets | 大括号 |
| `[ ]` | square brackets 或 brackets | 方括号 |
| `< >` | angled brackets | 尖括号 |
| `( )` | parentheses | 圆括号 |

### 5.8 冒号

（1）全角冒号引出解释和说明。

```
请确认以下几项内容：时间、地点、活动名称和来宾数量。
```

（2）表示时间时用半角冒号。

```
早上 8:00
```

### 5.9 省略号

（1）省略号 `⋯⋯` 表示语句未完，或语气不连续。

（2）省略号占两个汉字位置、包含六个点，不用 `。。。` 或 `...`。

（3）省略号不与“等”连用。

```
错误：我们为会餐准备了香蕉、苹果、梨…等各色水果。
正确：我们为会餐准备了各色水果，有香蕉、苹果、梨⋯⋯
正确：我们为会餐准备了香蕉、苹果、梨等各色水果。
```

### 5.10 感叹号

- 用平静的语气叙述，尽量不用感叹号。
- 不得连用 `！！` 或 `!!!`。

### 5.11 破折号

（1）破折号用于进一步解释。

（2）破折号占两个汉字位置；如果只占一个汉字位置，前后各留一个半角空格。

```
直觉————尽管它并不总是可靠的————告诉我，这事可能出了些问题。
直觉 —— 尽管它并不总是可靠的 —— 告诉我，这事可能出了些问题。
```

### 5.12 连接号

（1）连接号连接两个类似的词。

（2）直线连接号 `-` 占一个半角位置，用于两个名词的复合和图表编号。

```
氧化-还原反应
图 1-1
```

（3）数值范围用波浪连接号 `～` 或一字线 `—`，占一个全角位置。

```
2009 年～2011 年
```

（4）波浪连接号也可以用“至”代替。

```
周围温度：-20 °C 至 -10 °C
```

### 5.13 补充：代码与标点

- 行内代码、命令、路径、配置项用反引号包裹，内部标点保持原样。
- 中文和英文标点不混用：不写 `你好, 世界`，也不写 `Hello，world`。

## 6. 文档体系

### 6.1 结构

软件手册按“书”来组织，推荐结构如下。

| 章节 | 英文 | 必备性 | 形式 | 内容 |
| --- | --- | --- | --- | --- |
| 简介 | Introduction | 必备 | 文件 | 产品和文档本身的总体说明 |
| 快速上手 | Getting Started | 可选 | 文件 | 最短路径跑起来 |
| 入门篇 | Basics | 必备 | 目录 | 初级使用教程 |
| 环境准备 | Prerequisite | 必备 | 文件 | 使用前置条件 |
| 安装 | Installation | 可选 | 文件 | 安装方法 |
| 设置 | Configuration | 必备 | 文件 | 配置项 |
| 进阶篇 | Advanced | 可选 | 目录 | 中高级开发教程 |
| API | Reference | 可选 | 目录或文件 | API 逐项说明 |
| FAQ | FAQ | 可选 | 文件 | 常见问题 |
| 附录 | Appendix | 可选 | 目录 | 辅助内容 |
| 名词解释 | Glossary | 可选 | 文件 | 术语 |
| 最佳实践 | Recipes | 可选 | 文件 | 典型做法 |
| 故障处理 | Troubleshooting | 可选 | 文件 | 排错 |
| 版本说明 | ChangeLog | 可选 | 文件 | 变更记录 |
| 反馈 | Feedback | 可选 | 文件 | 反馈渠道 |

中英文名称要对应；章节顺序按读者的使用路径排，不按代码模块排。

### 6.2 文件名

- 文件名不含空格。
- 只用半角字符，不用中文。

```
错误：名词解释.md
正确：glossary.md
```

- 只用小写字母；`README`、`LICENSE` 等说明文件例外。

```
错误：TroubleShooting.md
正确：troubleshooting.md
```

- 多个单词用半角连字符分隔。

```
不佳：advanced_usage.md
正确：advanced-usage.md
```

### 6.3 补充：目录与链接

- 超过五屏的长文在开头给目录。
- 跨文档引用用相对路径；发布到其他渠道时再换成渠道要求的链接。
- 标题改动后同步更新目录锚点和站内链接。

## 7. 术语与翻译

### 7.1 首次出现

英文术语第一次出现时写全称并给中文，之后用缩写。形式统一为：

```
缩写（English Full Name，中文全称）
```

### 7.2 术语表

同一概念只用一种译法；项目开始时建术语表，写进 `glossary.md`。同一文档里“配置”与“设定”不要混用。

### 7.3 大小写

- 专有名词：每个词首字母大写。
- 普通名词短语：全小写。
- 产品名按官方写法，如 `iPhone`、`GitHub`、`macOS`，不写成 `IPhone`、`Github`。

### 7.4 不翻译的内容

代码、命令、路径、字段名、API 名、错误码、日志原文不翻译；确需解释时在括号里给中文。
