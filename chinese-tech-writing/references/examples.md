用法：写作时查“这样写错在哪”，审校时查“怎么改”。表格中的依据指向 `style-guide.md` 的对应条款。

## 2. 句子

| 反例 | 正例 | 依据 |
| --- | --- | --- |
| 本产品适用于从由一台服务器进行动作控制的单一节点结构到由多台服务器进行动作控制的并行处理程序结构等多种体系结构。 | 本产品适用于多种体系结构。无论是由一台服务器（单一节点结构），还是由多台服务器（并行处理结构）进行动作控制，均可以使用本产品。 | 文本·句子（1） |
| 那个昨天生病的人没有参加会议。 | 他昨天生病了，没有参加会议。 | 文本·句子（2） |
| 请确认没有接通装置的电源。 | 请确认装置的电源已关闭。 | 文本·句子（3） |

一逗到底的段落：

```text
反例：安装前需要检查系统版本，确认依赖已经安装，关闭防火墙，备份配置文件，然后执行安装脚本，安装完成后重启服务，最后验证端口是否监听。
正例：安装前先完成四项准备：检查系统版本、确认依赖、关闭防火墙、备份配置文件。然后执行安装脚本并重启服务。最后验证端口是否处于监听状态。
```

依据：标点符号·逗号（2）。

## 7. 结构与文件

### 标题跳级

```markdown
反例：

# 一级标题

### 三级标题

正例：

# 一级标题

## 二级标题

### 三级标题
```

依据：标题·1.2（1）。

### 孤立编号

```markdown
反例：

## 二级标题 A

### 三级标题 A

## 二级标题 B

正例：

## 二级标题 A

## 二级标题 B
```

依据：标题·1.2（2）。

## 8. 改稿前后对照

改前：

> 本工具被设计用来帮助用户在Windows系统下快速的进行日志文件的查看和分析，它支持多种不同的日志格式,包括文本格式以及JSON格式,用户可以方便的通过它来定位问题。

改后：

> 本工具用于在 Windows 系统下查看和分析日志文件。它支持文本和 JSON 两种格式，可以帮助你快速定位问题。

改动说明：

1. “被设计用来帮助用户”改为“用于”，去掉被动语态和空动词。
2. “快速的进行日志文件的查看和分析”改为“查看和分析日志文件”。
3. 长句拆成三句，每句一个意思。
4. 半角逗号改为全角逗号，中英文之间补空格。
5. “多种不同的”“方便的”属于冗余修饰，删除。
